Overview

I built Help Desk Sim to practice backend design in a more realistic scenario than a small CRUD exercise. It models tickets, technician notes, first-response and resolution SLAs, user roles, session history, outbound email events, and audit trails while still being simple enough to run locally without a database install.

  • ASP.NET Core API structure

    Organizes authentication, user management, ticket routes, dashboard metrics, lookups, notification history, and webhook callbacks in one backend-focused project.

  • Authentication and role handling

    Uses access tokens, refresh tokens, role-based protection, password reset flows, password change support, and active session plus revocation history.

  • Workflow thinking

    Splits first-response and resolution SLA targets, records audit history, retries failed notifications, and exports filtered audit results as CSV for review.

The flow

  1. Staff sign-in
  2. Ticket + notes
  3. SLA targets
  4. Audit history
  5. Email notification
  6. CSV export

Where it can grow next

The clearest next improvements are moving persistence to SQLite or SQL Server, adding a lightweight frontend dashboard, and extending reporting plus notification integrations.

Why it matters

Help Desk Sim shows that I can move beyond very small assignments and build something with multiple connected backend concerns. It gives employers a more realistic example of how I approach API structure and feature growth as a student developer.

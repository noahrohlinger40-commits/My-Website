Overview

I built LanSentinel to practice Java networking with a problem grounded in real device behavior. The current version scans devices on a local subnet, checks reachability, and returns IP address, hostname, online status, and response time in a structured format.

  • Java networking practice

    Uses Java networking classes to resolve IP addresses and test whether devices are reachable on a local network.

  • Structured output

    Includes a DeviceResult model for storing IP, hostname, online status, and response time data in a clean format.

  • Clear room for expansion

    The project can grow into a fuller dashboard with alerts, categorization, and historical tracking.

The flow

  1. IP, range or CIDR
  2. Parallel probes
  3. DeviceResult
  4. Console, CSV or JSON

Next version

The strongest next step is turning the console-focused work into a clearer dashboard experience with richer device history, easier filtering, and more visible reporting.

Why it matters

LanSentinel shows that I can apply class-level Java skills to a practical networking problem rather than only small isolated exercises. It is a straightforward example of student project work connected to a real technical idea.
